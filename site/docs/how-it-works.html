How it works

Two data sources, zero network calls, zero LLM calls.

Static analysis

haunt walks the given directory for every SKILL.md, parses its YAML frontmatter and markdown body with plain regular expressions, and checks:

  • every relative link in the body resolves to a real file
  • the frontmatter has a non-empty, non-trivial description
  • no two files resolve to the same skill name

Real-usage cross-reference

This is the part that's different from every other skill linter. Claude Code already writes a JSONL transcript of every session to ~/.claude/projects/<project>/<session>.jsonl. Each line is a message; an assistant message that calls a skill contains a tool_use block with name: "Skill" and an input.skill field naming it.

haunt reads every transcript under that directory, counts how many times each skill name was actually invoked, and cross-references that count against what's installed:

  • a skill with zero invocations is a ghost - loaded into context on relevant turns, never used
  • an invocation of a name with no matching SKILL.md is a hallucinated invocation - the agent called something that used to exist, or never did

The usage.json fallback

Not every agent runtime writes Claude Code's own transcript format. Some keep a simpler sidecar file instead - a flat {skill_name: {"use_count": N}} map. haunt reads one of these automatically if it finds .usage.json next to the scanned directory, or you can point it at one explicitly with --usage-file.

Why no LLM calls

Every check here is a deterministic fact about files that already exist on disk: a link resolves or it doesn't, a name is duplicated or it isn't, a skill was invoked N times or zero times. There is nothing here that benefits from a model's judgment, and adding one would only add cost, latency, and a source of non-determinism to a tool whose entire value is that the same input always produces the same answer.
