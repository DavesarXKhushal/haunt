The problem

Every Claude Code skill linter checks structure: valid frontmatter, a description that isn't empty, a link that resolves. None of them check whether a skill has ever actually fired. A skill can read perfectly, pass every structural check, and still never once get invoked, while silently costing tokens whenever its description looks close enough to trigger consideration.

Nothing in the file itself tells you that. Your session transcripts do - haunt reads them directly.

How it works

static Structural checks

Parses every SKILL.md's frontmatter and body: broken relative links, duplicate skill names, missing or thin descriptions.

transcripts Real-usage cross-reference

Reads the JSONL transcripts Claude Code keeps in ~/.claude/projects, finds every Skill tool invocation, and matches it against what's installed.

No LLM calls, no network access, no account required. Deterministic, offline, reads files already on disk.

Verified against a real production agent

We ran it against a live 379-skill agent built up over months of real daily use. Nobody had audited the whole tree end to end before.

One skill accounted for over 33,000 of those invocations by itself. The same run caught 10 broken file references and 24 descriptions too thin for an agent to route on.
