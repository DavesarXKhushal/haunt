The problem

A skill with a good description can still be dead weight.

Every Claude Code skill linter checks structure -- valid frontmatter, a non-empty description, a link that resolves. None of them check whether the skill has ever actually fired. A skill can read perfectly, pass every structural check, and still never once get invoked, while silently costing tokens every time its description looks close enough to trigger consideration. Nothing in the file itself tells you that. Your session transcripts do -- haunt reads them.

How it works

Static checks

Parses every SKILL.md's frontmatter and body: broken relative links, duplicate skill names, missing or thin descriptions.

Real-usage cross-reference

Reads the JSONL transcripts Claude Code already keeps in ~/.claude/projects, finds every Skill tool invocation, and matches it against what's installed.

No LLM calls, no network access, no account. Deterministic, offline, reads files already on your disk.

The numbers

We ran it on a live 379-skill production agent.

Hermes, the agent behind LocalHost, has 379 installed skills built up over months of real daily use. Nobody had audited the whole tree end to end before this.

379skills scanned
42,639real invocations matched
121never invoked once

One skill accounted for over 33,000 of those invocations by itself. The run also caught 10 broken file references and 24 descriptions too thin for an agent to route on.

Docs

Install

pip install haunt
# or, with no install:
uvx haunt /path/to/skills

Flags

FlagEffect
--projects <dir>Claude Code transcripts directory (default: ~/.claude/projects)
--usage-file <file>a .usage.json sidecar, for runtimes that keep one instead of transcripts
--jsonmachine-readable output for CI
--fail-on-ghostsnon-zero exit if any skill has zero real invocations

Checks

CheckSourceWhat it finds
ghost-skilltranscriptsinstalled, zero invocations in your session history
hallucinated-invocationtranscriptsinvoked by name, no matching SKILL.md exists
broken-referencestatica relative link that doesn't resolve
duplicate-namestatictwo SKILL.md files resolve to the same name
missing-descriptionstaticfrontmatter has no description
thin-descriptionstaticdescription too short for an agent to route on

CI

- name: Audit skills
  run: uvx haunt .claude/skills --fail-on-ghosts

As a Claude Code skill

Drop skills/haunt/ from this repo into your own skills directory and Claude Code will run haunt itself when asked to audit a skill library.
